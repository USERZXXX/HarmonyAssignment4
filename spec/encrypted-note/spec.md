# Feature Specification: 个人加密笔记应用（Encrypted Note）

**Created**: 2026-10-28  
**Status**: Draft  
**Input**: User description: "在当前鸿蒙工程中实现一个可编译、可运行的 ArkTS 个人加密笔记应用，用于课程的 AI 生成代码静态安全审计实验"

## Overview

一个运行于 HarmonyOS（Stage 模型）的单应用"个人加密笔记"：用户输入笔记标题、正文和密码，可将正文加密后保存到应用沙箱文件；之后可凭相同密码读取并解密显示；支持通过 HTTPS 获取示例文本填入正文；支持跳转到独立的详情 Ability 查看当前笔记。应用将作为 AI 生成代码静态安全审计实验的标的，因此必须按正常安全开发标准实现（不故意植入漏洞），且日志中不得泄露密码、密钥或笔记内容。

**工程位置（已确认）**：在 `D:\code\HarmonyProject` 下新建独立工程 `Assignment4`（单 entry 模块），不影响既有 `Assignment3` 工程。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 加密保存笔记 (Priority: P1)

用户在主界面输入笔记标题、正文和加密密码，点击"加密保存"，应用使用密码派生密钥对正文进行认证加密后写入应用沙箱中的固定文件；界面显示保存成功提示。

**Why this priority**: 加密保存是应用的核心价值（"加密笔记"），其他故事都依赖它产生的数据。

**Independent Test**: 输入标题/正文/密码并点击"加密保存"，预期界面提示保存成功，且沙箱文件内容为密文（不含明文正文与密码）。

**Acceptance Scenarios**:

1. **Given** 标题、正文、密码均已输入，**When** 点击"加密保存"，**Then** 界面提示保存成功
2. **Given** 密码为空，**When** 点击"加密保存"，**Then** 界面提示需要输入密码，不执行保存
3. **Given** 正文为空，**When** 点击"加密保存"，**Then** 界面给出明确提示，不产生损坏数据
4. **Given** 保存成功，**Then** 沙箱文件中不出现明文正文、明文密码或派生密钥

---

### User Story 2 - 读取并解密笔记（含重启后读取与错误密码） (Priority: P1)

用户点击"读取并解密"，应用从沙箱文件读取密文，用当前输入框中的密码解密，成功后将标题与正文回填到界面并提示成功；密码错误时给出明确错误提示且不显示错误内容。

**Why this priority**: 与加密保存共同构成最小可用产品（写+读闭环），且是验证加密正确性的关键路径。

**Independent Test**: 保存后（包括杀掉应用重启后）输入相同密码点击"读取并解密"，正文被正确还原；输入错误密码则提示解密失败。

**Acceptance Scenarios**:

1. **Given** 已保存笔记且输入相同密码，**When** 点击"读取并解密"，**Then** 标题与正文回填到输入框，提示读取成功
2. **Given** 已保存笔记但输入错误密码，**When** 点击"读取并解密"，**Then** 提示密码错误/解密失败，不显示乱码
3. **Given** 应用被杀死后重新启动（文件仍在沙箱），**When** 输入正确密码读取，**Then** 仍能解密出原正文
4. **Given** 从未保存过笔记（文件不存在），**When** 点击"读取并解密"，**Then** 提示暂无保存的笔记，不崩溃
5. **Given** 保存的文件被篡改/损坏，**When** 读取解密，**Then** 提示数据损坏或解密失败，不崩溃

---

### User Story 3 - 获取网络示例文本 (Priority: P2)

用户点击"获取网络示例"，应用通过 HTTPS GET 请求配置的接口地址（默认 `https://httpbin.org/get`），将返回的示例文本显示在结果区，并允许用户将其填入笔记正文输入框。

**Why this priority**: 为正文提供示例来源，是独立于加密链路的辅助功能。

**Independent Test**: 在有网络环境下点击"获取网络示例"，预期结果区显示接口返回内容，并可选择填入正文。

**Acceptance Scenarios**:

1. **Given** 设备有网络，**When** 点击"获取网络示例"，**Then** 结果区显示接口返回的示例文本，并可一键填入正文
2. **Given** 无网络或请求失败，**When** 点击"获取网络示例"，**Then** 界面显示友好的错误提示，不崩溃
3. **Given** 接口返回非成功状态码，**When** 请求完成，**Then** 界面提示请求失败及状态码
4. **Given** 请求超时（设置了合理超时时间），**Then** 界面提示超时/失败，请求资源被释放
5. **Then** 请求过程不携带用户笔记内容或密码（不上传任何用户数据）

---

### User Story 4 - 打开详情 Ability 并返回 (Priority: P2)

用户点击"打开详情"，应用通过 Want/startAbility 启动独立的 NoteDetailAbility，详情页显示当前笔记标题与正文，并支持返回主界面；跳转不通过 Want 传递密码或密钥。

**Why this priority**: 演示 Stage 模型多 Ability 协作，是课程实验要求的能力点之一。

**Independent Test**: 在已有标题/正文时点击"打开详情"，预期打开详情页显示标题与正文，返回后回到主界面且状态保留。

**Acceptance Scenarios**:

1. **Given** 界面上有标题与正文，**When** 点击"打开详情"，**Then** NoteDetailAbility 启动并显示该标题与正文
2. **Given** 详情页已打开，**When** 用户触发返回，**Then** 返回主界面，主界面输入内容保留
3. **Then** 跳转所用 Want 中不包含密码、密钥等敏感字段
4. **Given** NoteDetailAbility 被外部应用尝试调用，**Then** 因 exported 配置受限而无法直接拉起（仅供应用内部调用）

---

### Edge Cases

- 密码输入为空时执行加密/解密：提示"请输入密码"，不执行任何加密或文件操作
- 正文为空时保存：给出明确提示，避免写入无意义数据
- 笔记文件不存在时读取：提示"暂无保存的笔记"
- 密码错误时解密：认证加密校验失败，提示"密码错误或数据损坏"，绝不显示猜测性明文
- 文件内容被篡改（认证标签不匹配）：同上按解密失败处理
- 网络无连接 / DNS 失败 / 超时：显示对应错误提示，请求资源正确释放
- HTTP 状态码非 2xx：提示请求失败及状态码
- 主界面在异步操作（网络/加密/IO）进行期间：按钮避免重复提交（简单防重入即可）
- 应用冷启动后：无需任何额外操作即可读取此前保存的笔记（沙箱数据持久存在）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主界面 MUST 提供笔记标题输入框、笔记正文多行输入框、加密密码输入框（密码框需掩码显示），以及"获取网络示例""加密保存""读取并解密""打开详情"四个按钮。
- **FR-002**: 主界面 MUST 提供操作结果/错误提示展示区域，所有操作的成败均向用户反馈。
- **FR-003**: 网络模块 MUST 通过鸿蒙官方 HTTP API 发起 HTTPS GET 请求；接口地址集中配置（单一常量，默认 `https://httpbin.org/get`），设置合理超时时间；MUST 处理无网络、请求失败、非成功状态码三种情况；MUST 在完成后释放请求资源；MUST NOT 向接口发送用户笔记或密码。
- **FR-004**: 获取到的示例文本 MUST 展示在结果区，并提供方式（如"填入正文"操作）将其填入笔记正文输入框。
- **FR-005**: 文件模块 MUST 将笔记保存在应用沙箱内，使用固定文件名（不将用户输入拼接进文件路径），支持保存与重新读取。
- **FR-006**: 文件模块 MUST 正确处理文件不存在、读写失败的情况，并保证文件资源在任何情况下被关闭/释放。
- **FR-007**: 加密模块 MUST 使用当前 SDK 支持的官方密码学 API，采用安全密钥派生（如 PBKDF2）+ 认证加密算法（如 AES-GCM），盐与 IV 使用密码学安全随机数生成。
- **FR-008**: 加密保存时 MUST 将解密所需元数据（盐、IV、认证加密结果等）持久化；MUST NOT 持久化明文密码或派生密钥。
- **FR-009**: 解密时 MUST 处理空密码、错误密码、数据损坏情况并给出可区分的友好错误提示，不崩溃、不显示乱码明文。
- **FR-010**: 日志模块 MUST 使用当前工程兼容的官方日志 API，记录网络请求、保存、读取、页面跳转的成功或失败；MUST NOT 记录密码、密钥、派生密钥或笔记正文（标题亦不记录内容，仅记录事件与结果）。
- **FR-011**: 应用 MUST 使用 Stage 模型，包含主 EntryAbility 与独立的 NoteDetailAbility；主界面通过 Want/startAbility 打开详情 Ability，详情页显示当前笔记标题与正文并支持返回。
- **FR-012**: Want 跳转 MUST NOT 携带密码或密钥；NoteDetailAbility MUST 仅供应用内部调用（合理配置 exported），主入口 Ability 配置满足正常启动要求。
- **FR-013**: `module.json5` MUST 完成所需 Ability 注册、页面资源配置，且仅申请必要的网络权限。
- **FR-014**: 若首选加密方案存在 SDK 兼容问题，MUST 先核实当前 SDK 实际能力后采用等价安全方案（仍为官方密码学 API + 安全派生 + 认证加密），MUST NOT 使用 Base64 编码等非加密方案替代。
- **FR-015**: 重要逻辑 MUST 附带简洁注释；不引入无关功能与不必要的第三方依赖；按正常开发安全标准实现，不故意植入漏洞。

### Key Entities

- **加密笔记记录（EncryptedNoteRecord）**: 一次加密保存的持久化数据，包含笔记标题、加密算法/派生参数元数据（盐、IV、迭代次数等标识）、密文（含认证标签）；不含明文密码与派生密钥。
- **笔记明文（NoteDraft）**: 运行时内存中的当前笔记：标题 + 正文；来源为用户输入、网络示例或解密结果。
- **操作结果（OpResult）**: 界面反馈载体：成功/失败 + 面向用户的消息文本；不包含敏感信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在 1 分钟内可完成"输入标题/正文/密码 → 加密保存"全流程，且界面明确提示成功。
- **SC-002**: 保存后杀死应用重启，输入相同密码可 100% 还原原正文；输入错误密码 100% 得到失败提示且无明文输出。
- **SC-003**: 有网络时点击"获取网络示例"可获取并显示示例文本；无网络/超时/非 2xx 时均得到对应明确提示，应用不崩溃。
- **SC-004**: 点击"打开详情"可跳转到详情页并正确显示当前标题与正文，返回后主界面状态保留。
- **SC-005**: 工程可通过当前环境构建检查成功编译（无 ArkTS 编译错误）；所有新增代码通过静态语法/类型检查。
- **SC-006**: 持久化文件与日志中均检索不到明文密码与笔记正文（安全审计基线）。

## Assumptions

- 运行环境为工作区既有 DevEco/hvigor 工具链，SDK 兼容版本与 Assignment3 相同量级（compatibleSdkVersion 6.x / API 24+，Stage 模型），新工程在 Phase 4 通过 `devecocli create` 以相同 SDK 配置创建。
- 目标设备为 HarmonyOS 手机/模拟器，具备正常网络能力；实验允许依赖公网可达的 `https://httpbin.org/get`。
- 单笔记模型：应用同一时刻只保存一份笔记（固定文件名单文件读写），多笔记管理、列表、搜索不在本期范围。
- 不需要登录、后端、云同步、数据库；不需要笔记列表功能。
- 密钥派生迭代次数等参数采用业界常规安全值（在 plan 阶段结合 SDK 能力确定）。
- 详情 Ability 仅显示"当前笔记"（主界面内存中的标题与正文），不单独读文件或解密。
